# Live verification against SPEC.md's ACCEPTANCE CRITERIA

Generated by `scripts/verify_all.py` run against the actual running system
(all 4 local pods + the public Cloudflare tunnel + real GitHub), not
pytest's mocked/isolated suite. pytest proves the code is correct in
isolation; this proves the deployment as it actually runs behaves
correctly, end to end — the same things a human clicking through the app
would check.

**Run it yourself:**
```
.venv/Scripts/python.exe scripts/verify_all.py --admin-password <your admin password>
```
(or `$env:VERIFY_ADMIN_PASSWORD` / `export VERIFY_ADMIN_PASSWORD`). Without
a password, every check that needs a real login (auth, chat) is SKIPPED —
the script never guesses, stores, or logs the real password. It never
invokes the Claude Code CLI, so it's safe to re-run freely without costing
any AI subscription usage.

## Known FAIL: RAM over budget on Windows

Total idle RSS across the 4 pods measures ~500MB on this Windows dev
machine, against SPEC.md's 300MB target. This is a real, honestly-reported
number, not glossed over — see the README's "Measured RAM" section for the
full explanation: Windows doesn't give separate processes the same
copy-on-write shared-library pages Linux's `fork()` model does, and each of
the 4 pods independently loads a full FastAPI/SQLAlchemy/Pydantic/structlog
stack. **Not yet re-measured on Linux** (no cloud VM was available this
session) — this is the one concrete, actionable follow-up left for a real
deployment target.

## Deliberately not exercised live

- **Destructive MCP tools** (`cancel_workflow`, `rerun_workflow`,
  `trigger_rollback`) and the chat's rollback **"yes"** path: each would
  either burn real GitHub Actions minutes or actually dispatch a rollback
  against production state. All are covered by the mocked test suite
  (`tests/test_mcp_tools_cicd.py`, `tests/test_healer_chat_agent.py`), which
  exercises the exact same code path with the GitHub API mocked out.
- **Prompt injection** and **CI self-healing** (`break_ci_demo.py`): both
  require a real Claude Code CLI invocation to reproduce live, which costs
  the operator's Claude subscription usage. Per this verifier's design, it
  never spends that budget on its own — it cites the existing mocked e2e
  tests instead. A real, unmocked demonstration of the *runtime* self-healing
  path already exists: [PR #10](https://github.com/Deepak20466/ai-self-healing-app/pull/10),
  a genuine free-mode heal run with no mocking anywhere in the loop.
- **Cloud VM deployment + remote contract verification**: no cloud VM was
  available this session. `local_deploy.py`'s real good-deploy/forced-rollback
  cycle (both PASS above) is the closest available proxy — it exercises the
  identical atomic-release/migrate/smoke-test/rollback logic `deploy.yml`
  runs on a real VM, just against `localhost` instead of SSH.
